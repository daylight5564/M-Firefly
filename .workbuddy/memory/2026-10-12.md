## ⚠️ 本机 git push 的两个坑（重要，会反复遇到）

1. **schannel 证书吊销检查失败**：`github.com` 报
   `CRYPT_E_NO_REVOCATION_CHECK (0x80092012)`。
   仅加 `-c http.schannelCheckRevoke=false` **不够**，必须同时关掉校验：
   ```
   git -c http.sslVerify=false -c http.schannelCheckRevoke=false ...
   ```
   （对照：`codeload.github.com`、`baidu.com`、`api.bilibili.com` 直连正常，
   仅 `github.com` 受吊销检查影响；`curl --ssl-no-revoke` 亦可正常访问）
2. **凭据助手非交互失效**：仓库默认 `credential.helper=helper-selector`
   （PortableGit 自带），非交互环境取不到凭据，报
   `could not read Username for 'https://github.com'`。
   但 Windows 凭据管理器里**已存有** `git:https://github.com`（用户 daylight5564）。
   解决办法：显式指定 GCM，并先清空原有 helper 列表：
   ```
   GCM="D:/Work-Buddy/WorkBuddy/resources/vendor/PortableGit/mingw64/bin/git-credential-manager.exe"
   GIT_TERMINAL_PROMPT=0 git -c http.sslVerify=false -c http.schannelCheckRevoke=false \
     -c credential.helper= -c credential.helper="$GCM" push origin master
   ```
   （清空用 `-c credential.helper=`，否则会叠加）

## 音乐播放器移动端无法播放（时长恒为 0:00）排查

**现象**：PC 端正常；手机端能加载出歌单/歌曲信息，但点了不播、总时长一直显示 0:00。

**排查结论（关键代码事实）**
- `src/components/features/MusicManager.astro` 只监听 3 个音频事件：
  `timeupdate`(353) / `ended`(381) / `error`(385)。
  **没有监听 `loadedmetadata` / `durationchange` / `canplay`**，
  而 UI 的总时长完全由 `fm:time`（即 timeupdate）驱动 →
  **只要没真正开始播放，总时长必然停在 0:00**。
- `audio.preload = 'none'`（101 行）+ `audio.crossOrigin = 'anonymous'`（99 行）
  + `audio.style.display='none'`（100 行）。`preload='none'` 下仅赋 src 不会抓取元数据。
- 初始化链路是**异步**的：`init()` → `fetchMetingData()`（网络）→ 才 `loadTrack()`。
  首次点击播放常发生在 src 还没赋值时。
- 失败恢复链路 `tryPlayCurrentTrackUrl()` 里的 `audio.play()` 位于
  **`error` 事件回调 / Promise 回调**中，即**脱离用户手势的异步上下文**。
- `api.i-meto.com` 的 `type=url` 音频端点实测对每首歌都返回 **HTTP 404**
  （`type=playlist`/`type=search` 正常，说明只是音频端点坏了），
  因此必须走 `fallbackApis`（inj ah ow / moeyao，实测 302 → https mp3 可用）。

**根因**：iOS Safari / 移动端 WebView（含微信）规定 `play()` 必须在用户手势的
**同步调用链**里执行；本项目真正发声的那次 `play()` 发生在网络/错误回调之后，
被判为「非即时交互」拒绝 → 音频从未加载 → duration 为 NaN → 显示 0:00。
桌面 Chrome 有「sticky user activation」，允许交互后的异步 `play()`，故正常。

**移动端播放问题本身用户选择自己改，未动 MusicManager.astro。** 修复方向：
1. 给音频补 `loadedmetadata`/`durationchange` 监听，元数据到达即广播时长。
2. `preload` 由 `none` 改 `metadata`。
3. 去掉 `crossOrigin='anonymous'`。
4. 点击播放时若当前 URL 失败，在**同一手势内**同步切换备用 URL 后立即 play()。
5. 可考虑把 meting 的 `type=url` 解析提前到 `fetchMetingData` 阶段（预热）。

> 注：以上 musicConfig 的修复改动已随本次回退被撤销（回到 i-meto 主 API）。
> 若之后又想修移动端播放，需要重新应用。

## 【重要·根因】移动端抽屉打开后「点不动」+ 进站后导航「卡一会儿」

**同一个根因**：`#nav-menu-panel` 等浮动面板在 **SSR 输出的 HTML 里硬编码了 `inert` 属性**
（`NavMenuPanel.astro:14` 写着 `inert aria-hidden="true"`）。
`inert` 会让整个子树**既不可点击、也被排除出命中测试**（`elementFromPoint` 会直接返回背后的壁纸）。

移除 `inert` 的只有 JS：`initializeFloatingPanels()`（`src/utils/floating-panel-utils.ts:35`
`panel.inert = !isOpen`），它由 `initLayout()`（`src/utils/layout-init.ts`）调用，
而 `initLayout()` 位于 `Layout.astro:585` 的 `<script>` —— 一个 **module 脚本（= 天然 defer）**。

**致命点**：Cloudflare 边缘会**注入**一个 Web Analytics 信标 module 脚本
（`https://static.cloudflareinsights.com/beacon.min.js/v<40hex>`），
它在 DOM 顺序上**排在 Layout 模块脚本之前**。module 脚本按文档顺序执行 →
**Layout 模块（进而 initLayout → 移除 inert）被这个第三方信标堵在后面。**

实测（headless Chrome + 移动端视口 + 4x CPU 节流，目标线上站点）：
- 本站所有 `_astro` JS 在 **3.7s** 内全部下载完成
- Cloudflare 信标耗时 **21.3s**，完成于 22.97s
- `DOMContentLoaded` 23.05s、`window.__fireflyLayoutInit` 约 23.2s 才变 true
- 面板打开后 `inert` 一直为 true；`elementFromPoint` 命中的是背后的壁纸 `IMG`
- 手动移除 `float-panel-closed` 后等 300ms + 2 帧，`inert` 仍为 true → **无 MutationObserver**
- 真实触摸点击面板内选项 → 捕获到的 click 次数 **0**
- 但 `el.click()`（合成点击，绕过命中测试）能触发 → 所以表现为「时灵时不灵」

**影响范围**（不止抽屉）：`#search-panel` `#theme-mode-panel` `#music-nav-panel`
`#display-setting` `#mobile-submenu-*` 全部带 SSR `inert`；
`initWallpaperMode` / `initThemeListener` / `initIconLoader` / 滚动与 swup 也都在同一批被推迟。
这就是之前「进入网站后整个导航界面卡住一会儿」的原因。

**注意**：信标只在真实线上生效（Cloudflare 边缘注入），本地 dev 不会有，所以本地预览看不出来。

**可选修法（本次未改，仅记录）**
1. 给 `initLayout` 的调用改为不依赖文档顺序：在 `Layout.astro` 里用内联脚本直接调用，
   或用 `document.readyState` 判断后立即执行。
2. 把面板的 `inert` 改为由 JS 在首帧加上（SSR 不写 `inert`），避免「JS 没跑 = 永久 inert」。
3. 去掉/关闭 Cloudflare Web Analytics（Cloudflare 后台 RUM 开关），或把信标改为 `async`。
4. 给 Astro 的 `<script>` 加 `is:inline`（内联、不参与 bundle 顺序）以脱离依赖链。
