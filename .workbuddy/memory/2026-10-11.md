## 排查 Bilibili 追番页不显示数据

**现象**：`src/config/siteConfig.ts` 里 `bilibili.uid = "438021727"` 已填，`/bilibili/` 页面预览空白。

**根因**：B 站接口 `x/space/bangumi/follow/list` 对匿名请求返回
`{"code":53013,"message":"用户隐私设置未公开"}`。对比 UID 2 无需登录即可正常返回 →
说明该接口不需要登录，是**「公开我的追番」这个独立隐私开关**没开
（与"个人空间整体是否公开"是两个不同设置）。
开关位置：B 站 App → 我的 → 设置 → 安全隐私 → 空间隐私设置 → 开启「公开我的追番」。
用户开启后已复测通过（`code:0`，返回真实数据）。

**重要架构特性**：`/bilibili/` 的数据是**构建/开发时服务端拉取并静态渲染**（`bilibili.astro`
frontmatter 里 `await fetchBilibiliList()`）：
- `pnpm dev` 每次请求实时抓取 → 改完隐私开关立刻能在本地预览看到
- `pnpm build`（GitHub Actions runner 上执行）时抓取并烘焙进 HTML → **线上是快照，
  新增追番不会自动更新，必须重新构建部署；改配置后本地也要重启 dev server**

**部署链路**（`.github/workflows/deploy.yml`）：GitHub Actions → GitHub Pages，
触发条件为 push 到 `master` 或手动 `workflow_dispatch`；
`build.yml` 另外在 push/PR 时跑 `astro check` + `astro build`。
本地无 `dist/`，线上产物由 CI 构建。
`vercel.json` / `wrangler.jsonc` / `wrangler.toml` 也在，但当前生效的是 Pages 流程。

**风险点**：GitHub runner 是境外机房的 IP，B 站接口对这类 IP 可能返回
`-352 风控校验失败`，会导致构建出来的页面依旧为空。本机（上海移动 IP，直连）实测正常。

## 显示设置面板（displaySettingsConfig）默认值机制

**关键：`src/config/displaySettingsConfig.ts` 只管"面板项是否显示"（12 个 `*Switchable` 开关），
不设默认值。** 默认值来自各主题配置文件，由 `src/utils/setting-utils.ts` 的 `getDefault*()` 读取。
取值优先级：`localStorage 有记录则优先，否则用配置默认值`（见各 `getStored*()`）。

面板选项 → 默认值来源：
- 主题色相 → `siteConfig.themeColor.hue`（经 `ConfigCarrier.astro` 的 `data-hue`）
- 亮/暗/跟随系统 → `siteConfig.themeColor.defaultMode`（`LightDarkSwitch.svelte`）
- 文章列表布局 → `siteConfig.postListLayout.defaultMode` / `mobileDefaultMode`
- 卡片边框 / 跟随主题色 → `siteConfig.card.border` / `card.followTheme`
- 壁纸模式 → `backgroundWallpaper.mode`
- 全屏布局 → `backgroundWallpaper.fullscreen.layout`
- 水波纹 / 渐变 / 横幅标题 / 轮播 → `backgroundWallpaper.common.{waves,gradient,homeText,carousel}.enable`
- 透明度/模糊/卡片透明度滑块 → `backgroundWallpaper.overlay.{opacity,blur,cardOpacity}`
- 樱花 → `sakuraConfig.enable`（`src/config/effectsConfig.ts`）

**想强制锁定默认值**（覆盖访客已存偏好）唯一正规做法：把对应 `xxxSwitchable` 设为 `false`，
代码会 `localStorage.removeItem(...)` 回退到配置默认值。
